# 演示数据样例

## 模拟招标书（成员 B 提供）

### 文件名：`sample_tender.txt`

```text
某企业数字化系统建设项目招标书

一、投标人资格要求

1. 投标人必须是具有独立法人资格的企业，持有有效的营业执照，注册资本不低于500万元人民币。

2. 投标人近三年内具有至少3个类似数字化系统建设项目的成功案例，需提供合同复印件和甲方联系方式。

3. 项目经理需具有5年以上相关项目管理经验，持有PMP或同等认证证书。

4. 技术负责人需具有高级技术职称，且有3个以上同类项目技术负责人经历。

二、商务要求

1. 项目总预算为人民币500万元，投标人报价不得超过预算上限，否则按废标处理。

2. 付款方式：合同签订后支付30%，系统上线验收后支付60%，质保期满后支付10%。

3. 交付周期：合同签订后90天内完成系统部署并上线运行。

4. 质保期：系统验收合格后提供1年免费质保服务。

5. 售后服务：7×24小时技术支持，响应时间不超过2小时。

三、技术要求

1. 系统性能要求：
   - 支持至少1000个并发用户同时在线访问
   - 页面响应时间不超过3秒
   - 系统可用性达到99.9%以上

2. 系统架构要求：
   - 采用B/S架构，支持Chrome、Firefox、Edge等主流浏览器访问
   - 支持微服务架构，便于后续扩展
   - 前后端分离，前端采用Vue框架

3. 数据安全要求：
   - 数据需每日自动备份，备份数据保存期限不少于90天
   - 支持数据加密传输和加密存储
   - 具备完善的权限管理和审计日志功能

4. 集成要求：
   - 支持与企业现有OA系统集成
   - 提供标准RESTful API接口
   - 支持单点登录（SSO）

四、评分标准

1. 技术方案：40分
2. 项目报价：30分
3. 公司资质与案例：20分
4. 售后服务方案：10分
```

## 验证说明

| 文件 | 验证功能 | 预期结果 |
|------|----------|----------|
| sample_tender.txt | 招标文件解析 | 提取资格类≥2条、商务类≥3条、技术类≥4条、评分类≥1条 |
| sample_tender.txt | 优先级分配 | 资格、评分类为P0；技术、商务类为P1 |
| sample_tender.txt | 来源追踪 | 每条需求都有 source_text 和 source_ref |
| sample_tender.txt | 响应清单筛选 | 可按类别、优先级、状态筛选 |
| sample_tender.txt | 人工修正 | 可修改需求内容、状态、优先级 |
| company_qualification.txt | 资料入库与检索 | 可检索到企业资质相关内容 |
| case_study.txt | 资料入库与检索 | 可检索到项目案例相关内容 |

## 风险验证用例

1. 故意不响应某条 P0 资格要求 → 合规核查应发现高风险
2. 某条技术响应无资料来源支撑 → 合规核查应标记为风险
3. 项目名称在响应中写错 → 合规核查应发现不一致
